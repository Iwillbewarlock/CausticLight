# CausticLight 빛 직접 계산 방식 설계 (영사기 상자 → 조명 셰이더)

2026-09-28. 영사기 상자는 게임 안에서 벽과 바닥을 따라 휘어 비추는 것까지는 됐지만 문제가 넷 있었다.
1. 밝기가 계획(+35 %)보다 훨씬 셌다 (선이 주변보다 약 6배).
2. 몇 프레임마다 물빛 전체가 사라졌다 나타났다 (번쩍임). 원인은 확정하지 못했다.
3. 위를 보는 바닥에도 맺혔다 (물에 튕긴 빛은 위로만 가므로 틀림).
4. 상자 모서리가 네모로 보였다.
사용자 판단으로 영사기를 접고, 게임의 모든 면을 밝히는 조명 셰이더에서 반사광을 직접 계산한다.

## 1. 원리

- 물은 거울이다. 등불 빛이 수면에 튕겨 벽에 닿는 것은, **수면 아래에 뒤집힌 등불(거울상)** 이 벽을 비추는 것과 같다.
- 그 빛이 수면을 지난 지점에서 물빛 무늬를 읽어 밝기에 곱한다.
- 보통 조명과 똑같이 **면의 방향(법선)** 을 쓰므로, 거울상 빛(아래에서 위로 오는 빛)을 등진 면, 즉 위를 보는 바닥은 받지 않는다.
- 조명 셰이더가 그리는 모든 것(벽, 기둥, 버섯, 통, NPC)에 같은 방식으로 적용된다. 상자가 없으니 네모 모서리도 없다.

## 2. 걷어내는 것 (단순해진다)

| 지금 | 새 방식 |
|---|---|
| 구역마다 게임 안에 판·상자 물체와 보이지 않는 조명을 놓음 (배치, 세이브 중복 방지, 버려진 것 정리) | 없음. 구역은 목록(데이터)일 뿐 |
| 판·상자 모델(NIF), 재질 색·크기 조작, 층별 숨기기, 재생 속도 컨트롤러 | 없음 |
| `Effect.hlsl` 패치 | 없음 (원본 그대로 돈다) |
| 빈 재질 값에 숫자를 억지로 끼워 넣음 | 플러그인이 만든 데이터 묶음 하나를 셰이더에 꽂음 |

ESP 는 쓸모가 거의 없어진다(원본 폼 2개를 아무도 쓰지 않음). 로드 오더 표시용으로만 남길지 나중에 정한다.

## 3. 새로 하는 것

### 플러그인 (매 프레임)
- `zones.json` 의 구역 목록을 읽는다. **구역 = 물 영역**: 수면 높이, 물 사각형(월드 좌표 두 모서리), 영향 높이.
- 구역마다 핵심 광원(이미 만든 선택 로직: 배치 등불 / 동적 광원 / 해), 물결 세기, 층 비중, 물속 생물 고리, 재생 시계를 계산한다 (이미 만든 로직 그대로).
- 이것을 **구조화 버퍼 하나**(구역당 몇 줄)에 써서 픽셀 셰이더 **t41** 에 꽂고, 무늬 그림 3장을 **t42~t44** 에 꽂는다.
  - 빈자리 확인: Community Shaders 셰이더 전체에서 t41~t44 를 쓰는 곳 없음 (VERIFIED, 전체 검색). 상수 버퍼(b0~13)와 샘플러(s0~15)는 모두 쓰이고 있어서 쓰지 않는다. 샘플러는 기존 색 샘플러를 빌린다.
  - 꽂는 시점: 먼저 매 프레임 한 번(기존 프레임 훅). 게임이나 CS 가 그 자리를 비우면 DTD 에서 검증된 방식(조명 셰이더가 물체를 그리기 직전 훅)으로 바꾼다.
- 무늬 그림은 게임의 텍스처 불러오기 경로로 연다(직접 DDS 를 읽지 않음).

### 조명 셰이더 (`Lighting.hlsl` 패치)
- 넣는 자리: 모든 점광원을 더한 직후 (`diffuseColor += lightsDiffuseColor;` 바로 앞).
- 구역이 0개면 곧바로 건너뛴다. 패치가 깔려 있어도 쓰지 않으면 비용 0.
- 픽셀마다, 구역마다 (최대 4개):
  1. 구역 사각형과 높이 밖이면 건너뜀.
  2. 핵심 광원을 수면 아래로 뒤집고, 거기서 이 점까지 선이 수면을 지나는 점 w 를 구함.
  3. w 가 물 사각형 밖이면 건너뜀 (가장자리는 부드럽게).
  4. 더하는 빛 = 광원 색 × 거리 감쇠 × **수면 반사율**(정면 약 4 %, 비스듬할수록 커짐) × **면이 그 빛을 향한 정도(N·L)** × 무늬.
- 확산광만 더한다 (광택 반사는 나중).
- `debugTint` 설정: 켜면 구역 안 픽셀에 무늬 없이 옅은 색만 입힌다. 스크린샷 한 장으로 "데이터가 셰이더에 닿지 않음" 과 "계산이 틀림" 을 가른다.

## 4. 물 영역 정하기

- 1차: 구역마다 **물 사각형**을 F10 두 번(수면 위 두 모서리)으로 찍어 `zones.json` 에 저장.
- 2차(나중): DTD 의 "플레이어 주변 지도" 방식으로 아래로 선을 쏴서 물이 보이는 곳을 자동으로 찾는다.
- 기존 도둑길드 구역 4개는 벽 기준이라 새 형식과 맞지 않는다. 지운다.

## 5. 게임 밖 검수

- 조명 셰이더는 조합이 아주 많다. `CommunityShaders.log` 에 실제로 찍힌 조합(`Lighting:Pixel:...`)을 그대로 골라 원본과 패치본을 fxc 로 컴파일해 비교한다.
- 구역 0개일 때 패치본이 원본과 같은 결과인지(건너뛰기만 추가됐는지) 확인한다.
- 플러그인: 버퍼 내용 계산을 시험으로 검사한다.

## 6. 게임 안 확인 (한 번)

- 설치 후 첫 실행은 조명 셰이더를 많이 다시 컴파일해서 **몇 분 동안 끊길 수 있다.** 그다음부터는 디스크 캐시.
- DevBench 로 카메라를 고정해 두고 6장을 연속으로 찍어, 켜졌다 꺼졌다 하는지 숫자로 잰다. 테스트하는 약 2분 동안은 캐릭터를 움직이지 않아야 한다.
- 순서: debugTint 로 데이터 도착 확인 → 무늬 켜고 밝기 측정(+10~35 % 목표) → 바닥에 안 맺히는지 → 물속 생물 고리.

## 7. 최적화

| 단계 | 방안 | 효과 |
|---|---|---|
| 셰이더 조합 | 먼 지형(LOD), 그림자·깊이 전용 조합에는 코드를 아예 넣지 않는다 (컴파일 시점에 뺌) | 먼 풍경과 그림자 계산은 원래 비용 그대로 |
| 구역이 없을 때 | 구역 수 0 이면 첫 줄에서 끝 | 물가가 아닌 곳에서는 비용 0 |
| 구역이 있을 때 | 픽셀마다 먼저 "이 구역 상자 안인가"만 본다 (덧셈·비교 몇 개). 밖이면 무늬를 읽지 않는다 | 물가에서 먼 화면 부분은 거의 공짜 |
| 무늬 읽기 | 비중 0 인 층은 읽지 않음 (최대 2층) × 앞뒤 장면 2장 = 최대 4번. 멀리 있는 면은 작은 밉맵을 읽음 | 가까운 물가 벽에서만 제대로 된 비용 |
| 구역 수 | 플러그인이 카메라에서 먼 구역(약 43m 밖)은 버퍼에 넣지 않음. 한 번에 최대 4개 | 픽셀당 반복 횟수 상한 |
| 거리 | 카메라에서 먼 픽셀은 반사광을 서서히 줄여 끔 | 멀리 보이는 물가에 비용을 안 씀 |
| 그리기 횟수 | 판·상자를 따로 그리지 않음 (영사기 방식은 구역마다 최대 2번 더 그렸음) | 영사기보다 오히려 가벼움 |
| 플러그인 (CPU) | 매 프레임 작은 버퍼 하나(구역 4개 × 수백 바이트) 갱신만. 판단은 지금처럼 초당 1~10번 | 사실상 0 |
| 메모리 | 무늬 그림 16MB 그대로 + 버퍼 1KB 미만 | 변화 없음 |
| 컴파일 | 추가 코드를 함수 하나로 묶어 크기를 줄임. 첫 실행만 몇 분, 이후 디스크 캐시 | 한 번뿐 |

## 8. 영사기 상자 판의 게임 안 결과 (기록)

- 됨: 벽·기둥·바닥을 따라 휘어 비춤, 핵심 광원 선택과 색, 구역 배치.
- 안 됨: 밝기 약 6배, 프레임 사이 켜짐·꺼짐(원인 미확정), 바닥에 맺힘, 상자 모서리.
